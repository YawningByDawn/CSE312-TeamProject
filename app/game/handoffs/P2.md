### API notes (cutscene + app shell) — all additive
- `preloadMineRenderer(seed, budgetMs=12) → MineRendererLoad` starts the bake in the background:
  ONE slice (≈ budget, worst unit ≈ 25–50 ms on this loaded box) per displayed frame, run just
  after paint (`slice.ts nextFrame`), so a 60 fps scene keeps its frames. `load.progress` 0..1,
  `load.promise`, `load.finishSync()`. `createMineRendererAsync(seed)` → Promise<MineRenderer>.
  `createMineRenderer(seed)` (sync) reuses a pending preload and finishes it at once.
- `renderer.ready` (always true once constructed).
- NEW `renderer.flushComposite(settleFog = true)`: jumps running fog fades to their targets (unless
  false) and recomposes the whole Sensed/Void composite at full resolution synchronously (one-off
  ≈ 30–60 ms). NEW getter `renderer.converged`: no fade running and nothing stale — the next frame is
  final/deterministic. Cutscene: please switch from the private `staleN` / `fog.transitioning` to
  these (the private names still exist for now).
- Console: the bake no longer reads back with getImageData on a non-willReadFrequently canvas (flush
  is a 1×1 drawImage snapshot, `flushCanvas` in bake.ts) — no Chrome readback warning.
