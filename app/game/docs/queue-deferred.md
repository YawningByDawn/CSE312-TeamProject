# Queue (deferred)

Rows whose next step waits wholly on the owner, in the Live row format of `docs/queue.md`. A row returns to `docs/queue.md` the turn the owner answers.

| Item | Goal | State |
|---|---|---|
| BAKE | Bake everything, and ship only "place sprite, pick frame". Move people, props, crystals, effects, terrain and lights to baked sheets, made once by offline scripts. The scripts stay out of the shipped bundle. Delete every runtime drawing function that has a baked twin: the old prop painters, render/art, the people-casting code, and the theme code that redraws things at load. Delete ground-2 (the rejected walls): about 1 MB of images plus a test that breaks whenever the rock code changes. A runtime renderer that only places sprites should be about 5–8k lines, not 70k. / Nothing should draw live. Only assets can be used. NOTHING | waiting on the owner: the next bake. People are baked cut-out parts (card bake-people-parts, approved); props, crystals, effects, terrain and lights still draw live. |
| MOVE | add to queue, find a good time to copy everything over to the cse312-team project repo and start working in that repo / https://github.com/YawningByDawn/CSE312-TeamProject This is the repo that we are to copy and work into / This is also not a small task. Can you scope integration into it? Beware of rate limits and such. The game will eventually be multiplayer / No history / Server runs the game, communicates to client via web socket. Since this is turn based it's not very latency intensive. / Here are the requirements for the project which has been developed in the backend section you are to maintain these requirements (verbatim in `docs/cse312-requirements.md`) / there would be a versus mode and a coop mode where gods will either share/compete over resources / yes live clock / wait until finished then move | waiting on the owner: card intro-cavern; the copy follows rb-switch (SHRINK), lean src only, no history. Versus and coop run on a live clock (Objective 3). |
| CUTS | Cut features that don't earn their lines. Every flag and A/B switch (?props11, ?gl, ?veins, ?crystals=2 and so on). Each wins and becomes the only path, or gets deleted. Half-built systems: finish them or remove them (the owner's §40 rule). The interface down to what you asked for: one-line cards, the stats numbers, the characters menu. Nothing else. Cut the mine crowd, the ghost people and the region tooltips. / Builder hover only a minimal tooltip of its name, regions for now remove. | waiting on the owner: props11, crystals. |
| GUARDS | Rules that stop the mess from returning. A hard line ceiling that fails the build: about 30–40k lines for src/ run code, with a per-folder cap. The old 80k ceiling existed and nobody enforced it. A check that fails if any shipped file isn't reachable from main.ts. That catches dead code at once. No file over about 400 lines. No new dev sheet or flag without a deletion date. Every change deletes what it replaces, in the same commit. No "keep the old path until later." Frame-cost guard: a test that fails if a frame makes more than the agreed draw calls or any texture upload at rest. | waiting on SHRINK. |
