# Queue (live head)

Open rows only; solved rows move to `docs/queue-log.md`. The queue is not history.

## Entry rules

- **Order to row.** Every owner order for work gets a row the same turn, before any spawn: order ids in the first cell, the owner's words verbatim in the Goal, joined by ` / `. A follow-up adding to a row is appended to that row's Goal verbatim. `<!-- order: <id> non-queue -->` marks only a message that orders no work: a question, a comment, an answer. A message that orders, narrows, rescopes or rules on work is queue, however short or angry.
- **No false rows.** A spawn, brief or commit names only the row whose Goal covers its work. Never route around a gate.
- **Live row:** `| ITEM (order ids) | goal | state |`. A State starts with exactly one of `working: <what is being done, branch>` (an agent is on it) or `waiting on <who or what>: <facts>`, then current facts only (limits: `contract.md`, Work). Each update replaces it, never appends.
- **The queue is ordered work for agents to clear now.** A row enters only when the owner orders work, never from discussion or the coordinator's own ideas. A row with no agent whose State names no wait is a fault: staff it the turn a slot frees, or close it. A row whose next step waits wholly on the owner moves to `docs/queue-deferred.md` until the owner answers.
- **Done.** A row is done when it lands and leaves for `queue-log.md` that turn. Visual work lands only after the owner approves its card; unapproved, its State is `waiting on the owner: card <id>`. Non-visual feel work waits on `playtest <id>` the same way; land.py keeps that row Live.
- **Deferred row** (`docs/queue-deferred.md`): waits on the owner; no agent builds from it; State `waiting on the owner: <what>`. Moving a row between the files is no drop.
- One row goes to one agent. A new topic gets a new row.
- **Forwarding.** A work spawn names a Live row, `queue: <row id>`; `misc` (research) names none. Its branch marks that row at hand-back (`contract.md`, Work).
